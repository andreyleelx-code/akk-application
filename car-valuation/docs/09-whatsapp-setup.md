# WhatsApp: что сделать руками и что уже готово в коде

Подключение через официальный **Meta Cloud API** — напрямую, без платного
посредника (Wazzup, Chat2Desk и т.п.). Дольше на старте на 1–3 дня
(верификация в Meta), зато без абонентской платы провайдеру.

## Что уже есть в коде

- `src/carval/whatsapp/client.py` — отправка сообщений и шаблонов, скачивание
  фото/голосовых. 5 тестов (`tests/test_whatsapp_client.py`).
- `src/carval/whatsapp/webhook.py` — приём сообщений: проверка подписи
  (чтобы никто чужой не мог слать поддельные сообщения), разбор в понятный
  формат. 6 тестов (`tests/test_whatsapp_webhook.py`).
- `src/carval/whatsapp/router.py` — распределение на менеджера/агента по
  тем же правилам, что в `leads.py` (тот же клиент — тот же менеджер, новый —
  по кругу), и грубое распознавание «похоже на оплату» для чата-кассы.
  8 тестов (`tests/test_whatsapp_router.py`).
- `src/carval/whatsapp/main.py` — готовый сервер: принимает сообщение,
  определяет менеджера, отвечает клиенту коротким подтверждением.
  Запуск: `carval-whatsapp` (после `pip install -e .`).

Чего здесь **пока нет**: полноценного агента с бронью, как в
`demo/agent.html` (поиск машин, расчёт цены, заявка). Это следующий шаг,
и ему нужен реальный календарь — то есть RentProg. Без него агент либо
врёт про наличие, либо ничего не бронирует. Сейчас сервер только
принимает сообщения и направляет их по менеджерам.

## Шаг 1. Номер и Meta Business

1. Нужен номер телефона, который **ещё не привязан** к обычному приложению
   WhatsApp (или вы готовы его отвязать — тогда обычное приложение на нём
   перестанет работать). Проверьте заранее, какой номер используете для
   программы.
2. Зайти на [business.facebook.com](https://business.facebook.com) →
   создать Business-аккаунт компании (если его ещё нет).
3. В Meta for Developers ([developers.facebook.com](https://developers.facebook.com))
   создать приложение (App) типа **Business**, подключить к нему продукт
   **WhatsApp**.
4. В разделе WhatsApp → API Setup добавить номер телефона, пройти
   верификацию (SMS или звонок с кодом).

## Шаг 2. Собрать три значения

В том же разделе **WhatsApp → API Setup**:

- **Temporary access token** (на 24 часа, для теста) или постоянный
  **System User token** (для работы — создаётся в Business Settings →
  System Users, с правами `whatsapp_business_messaging`).
  → `WHATSAPP_ACCESS_TOKEN`
- **Phone number ID** (число, показано там же рядом с номером).
  → `WHATSAPP_PHONE_NUMBER_ID`
- **App secret** — в настройках приложения, Settings → Basic.
  → `WHATSAPP_APP_SECRET`

Четвёртое значение придумываете сами — любая случайная строка:
→ `WHATSAPP_VERIFY_TOKEN` (например, `openssl rand -hex 16`).

Впишите всё это в `.env` рядом с остальными ключами (пример — в
`.env.example`).

## Шаг 3. Запустить сервер и дать его увидеть Meta

Вебхуку нужен публичный HTTPS-адрес. На старте для теста можно
пробросить локальный порт наружу (ngrok, Cloudflare Tunnel), на
рабочем сервере — обычный домен с SSL.

```bash
pip install -e .
carval-whatsapp          # поднимает сервер на :8080, путь /webhook/whatsapp
```

В Meta for Developers → WhatsApp → Configuration → Webhook:
- Callback URL: `https://ваш-адрес/webhook/whatsapp`
- Verify token: то же значение, что в `WHATSAPP_VERIFY_TOKEN`
- Подписаться на событие **messages**

Meta сразу же пришлёт проверочный запрос на этот адрес — если сервер
запущен и токен совпадает, подписка пройдёт.

## Шаг 4. Проверить

Напишите с личного телефона на рабочий номер. В логах `carval-whatsapp`
должна появиться строка вида:

```
Лид от 77011112233 (Имя) -> Ерлан
```

Если `WHATSAPP_ACCESS_TOKEN` настоящий — клиенту придёт короткое
подтверждение, что сообщение получено.

## Важные ограничения Meta Cloud API

- **24-часовое окно.** Отвечать клиенту обычным текстом можно только в
  течение 24 часов после его последнего сообщения. Написать первым
  (например, напоминание о возврате депозита через несколько дней)
  можно только заранее одобренным **шаблоном сообщения** — заводится в
  Meta Business Manager → WhatsApp Manager → Message Templates,
  проверяется Meta 1–2 дня. В коде это `client.send_template(...)`.
- **Тестовый номер** (в Development-режиме приложения) может писать
  только на несколько заранее добавленных номеров получателей. Чтобы
  снять это ограничение, приложение переводится в Live-режим — для
  этого Meta проверяет Business-аккаунт (Business Verification),
  обычно 1–3 дня.
- **Один номер — одно место.** Если номер уже в обычном приложении
  WhatsApp, перенос на Cloud API отключит его там. Второй рабочий номер
  для обычных чатов сотрудников можно оставить как есть, а именно этот —
  только под API.
