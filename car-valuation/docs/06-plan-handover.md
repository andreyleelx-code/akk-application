# 6. Пошаговый план, передача проекта и где собирать

## Шаги

1. **Суббота: разведка, не продажа.** Узнать, как проходит оценка, где чаще всего ошибаются, сколько стоят ошибки, сколько машин в день и в каком виде есть прошлые данные. → [вопросы](meeting/saturday-discovery.md)
2. **Попросить 20–50 прошлых кейсов** с фото и итогом: это главный тест. → формат в `data/cases/README.md`
3. **За 3–5 дней собрать прототип:** Telegram-бот, чек-лист съёмки и отчёт по кузову. Прогнать на их старых кейсах и показать, что поймал ИИ, а что нет. → бот и `python -m carval.backtest` уже готовы
4. **Пилот на 2 недели:** ИИ работает параллельно с оценщиками, расхождения фиксируются и разбираются.
5. **Договор и передача** после подтверждённой точности: аккаунты, документация, обучение, поддержка.

## Как передать проект

Создавайте всё на **аккаунтах заказчика**: их API-ключ, их Supabase, их VPS, их Telegram-бот. Вам остаётся роль администратора по договору. Это защищает их от привязки к вам, а вам даёт чистую позицию.

Чек-лист передачи:

- [ ] Ключ Claude API создан в организации заказчика (console.anthropic.com), вы приглашены участником
- [ ] Проект Supabase в аккаунте заказчика, миграция применена
- [ ] VPS оплачен заказчиком, бот запущен там
- [ ] Telegram-бот создан через @BotFather с телефона заказчика
- [ ] Документация (эта папка) передана
- [ ] Видеоинструкция на 10 минут для оценщиков записана
- [ ] Резервная копия БД сделана и передана
- [ ] Выгрузка промптов (`prompts/`) и настроек (`config/`) передана

## Где собирать

- **Разработка:** отдельный Project в Claude (инструкции, чек-листы, примеры). Удобен для проектирования и тестов промптов, но не для ежедневной работы оценщиков.
- **Рабочая система:** связка Telegram + Supabase (+ n8n, когда понадобятся интеграции). Для ежедневной работы команды нужен бот.
